# 017: Explicit ChangeSet Domain Model for Multi-File Mutations

## Context
ForgeAI previously controlled mutation scope via an `affected_files` list generated by the `PlanningAgent`. While this sufficed for isolated fixes, it proved insufficient for coordinated refactoring (e.g. module extraction, interface changes) which requires mutating both primary files and their dependents. We needed a secure way to dynamically authorize dependency-discovered files without granting the LLM unlimited repository-wide write access.

## Problem
How do we support multi-file structural changes that require modifying newly discovered dependent files, while strictly maintaining our primary security invariant ("LLMs propose actions; the application authorizes and executes them") and preventing runaway cascading modifications?

## Decision
We introduce a structured `ChangeSet` domain model alongside a deterministic `ChangeSetPolicy`.

1. **Explicit Proposals**: The `PlanningAgent` generates a `ChangeSet` mapping `CREATE`, `MODIFY`, and `DELETE` operations.
2. **Deterministic Expansion**: The LLM cannot authorize itself. The `ChangeSetPolicy` evaluates the LLM's proposal, applying hard limits (`coding_max_changed_files`), evaluating `.gitignore` and `excluded_files`, and rejecting path traversal or sensitive file access.
3. **Auditable History**: The resulting `AUTHORIZED` ChangeSet retains a full `expansion_history` detailing why each file was approved or rejected.
4. **Post-Validation Completeness**: `CodingAgent` enforces that the resulting git diff strictly adheres to the authorized ChangeSet, rolling back if an unauthorized file was modified or if a required operation (like a planned deletion) was ignored.

## Consequences
- **Positive**: We can safely support complex refactoring tasks spanning multiple files.
- **Positive**: We retain a strict, auditable boundary between LLM proposal and application authorization.
- **Negative**: The planning prompt becomes more complex, requiring the LLM to understand and output detailed relationships.
- **Negative**: Adds slight overhead to the `CodingAgent` execution loop due to rigorous post-change validations.
